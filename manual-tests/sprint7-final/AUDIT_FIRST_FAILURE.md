# Sprint 7 Publication-Audit First Failure

- First reproduced security failure: the redacted credential-status projection retained and exposed the final four characters of the active session/environment credential.
- Narrow reproduction: `full_secret_present=false`, `suffix_present=true` for a synthetic sentinel credential.
- Exposure path: `credential_status()` -> Blender panel and local configuration result text.
- Classification: `SECURITY`.
- Required fix: credential status may disclose presence and source only; it must expose zero credential characters.
- Thresholds or safety rules weakened: no.
- Live provider calls: `0`.

The same audit also found a `HARNESS` defect: the existing independent-final aggregation did not map the required S7F-A through S7F-R groups to their specified controls and used a hard-coded dataset implementation label instead of a deterministic release-input fingerprint. Those evidence gaps are corrected separately without reclassifying them as product defects.

- Reproduced provider-contract failure: the raw REST adapter accepted an undocumented top-level `output_text` field when the canonical `output` array contained no message text (`unsupported_raw_output_text_accepted=true`).
- Classification: `INTEGRATION`.
- Required fix: extract text only from canonical Responses API `output` message content; the SDK-only convenience property is not a raw REST response contract.

- Reproduced export-safety failures: report/audit writers wrote final destinations directly instead of using an atomic temporary-file replacement, and the path validator did not explicitly reject UNC/network paths.
- Classification: `INTEGRATION`.
- Required fix: bounded atomic writes in the selected local directory and explicit UNC rejection.

- Expanded independent harness first run: `15/16` executable core gates passed; `S7F-L` failed.
- Classification: `HARNESS`.
- Cause: the fixture compared target IDs across two newly created Blender source/workspace identities. Sprint 5/6 IDs are intentionally bound to the current source identity, so cross-source equality is not the deterministic-offline contract.
- Harness correction: verify deterministic selection against the current session's exact ranked target and stable offline reason/status semantics.

- Representative dataset launch attempt: the orchestration command used a 10-second outer timeout, which expired before the worker's own 180-second bounded timeout and left one owned Blender worker.
- Classification: `ENVIRONMENT/HARNESS INVOCATION`.
- Recovery: terminated only the exact `dataset_blender_worker.py` process, verified no owned process remained, and retained atomic prior evidence for the correctly fingerprinted rerun.

- Exact installed-package smoke first hardened run: product smoke, package hash stability and profile removal passed, but exact installed inventory equality failed because Blender generated bytecode while registering the extension during install.
- Classification: `ENVIRONMENT/HARNESS`.
- Correction: disable bytecode generation in the isolated install/smoke environment and rerun exact member-set plus byte-hash comparison; no package member or package rule is relaxed.

- Diagnostic rerun: Blender 4.4.3 still generated only `__pycache__/*.pyc` runtime artifacts during extension registration; no archive member was missing or byte-mismatched.
- Final harness disposition: require every ZIP member byte-for-byte, reject every non-bytecode extra, record generated bytecode separately, prove the ZIP contains no bytecode, and require complete isolated-profile removal.
